# КиноПарк — система покупки билетов и выбора мест

Учебный проект: сайт сети кинотеатров с базой данных. Здесь можно выбрать фильм и сеанс, указать места на схеме зала и оплатить их (оплата учебная). Билет приходит с QR-кодом, по которому проходят в зал. Цены динамические, есть предзаказ из бара и панель администратора.

## Как запустить

Нужен только **Node.js 22.13 или новее** (с nodejs.org, версия LTS). Внешних библиотек нет, `npm install` не нужен. SQLite тоже встроен в Node.js, отдельно его ставить не нужно.

1. Откройте папку `kinopark` в VS Code (File → Open Folder).
2. Откройте терминал: Terminal → New Terminal.
3. Выполните:
   ```
   npm start
   ```
4. Откройте в браузере **http://localhost:3000**

Ещё можно нажать **F5** в VS Code: запустится сервер в режиме отладки.

При первом запуске сервер сам создаёт базу `data/kinopark.db` и заполняет её демо-данными: 2 кинотеатра, 5 залов, 12 фильмов и расписание на 7 дней вперёд. При каждом следующем запуске расписание дописывается, поэтому сеансы не заканчиваются.

| Аккаунт | Email | Пароль |
|---|---|---|
| Администратор | admin@kinopark.ru | admin123 |
| Зритель | demo@kinopark.ru | demo123 |

Для оплаты подходит тестовая карта `4242 4242 4242 4242`, любой срок в будущем и любой CVC.

Команды:
- `npm start` — запуск;
- `npm run dev` — запуск с автоперезапуском при изменении кода;
- `npm run reset-db` — удалить базу, при следующем запуске она создастся заново.

Посмотреть базу можно расширением VS Code **SQLite Viewer** (открыть `data/kinopark.db`) или программой **DB Browser for SQLite**.

## Что умеет сайт

**Зритель**
- Афиша: «Сейчас в кино» и «Скоро» (с предпродажей), фильтры по жанру и кинотеатру, поиск.
- Страница фильма: описание и расписание по дням, кинотеатрам и залам. У каждого сеанса видны цена и заполненность зала.
- Схема зала: обычные места, VIP, диваны (продаются парой). Занятые места обновляются каждые 20 секунд.
- Бронь мест на 10 минут с таймером. Если не оплатить вовремя, места освобождаются.
- Предзаказ из бара («Попкорн без очереди»).
- Учебная оплата картой: номер проверяется по алгоритму Луна, в базе сохраняются только последние 4 цифры.
- Личный кабинет: билеты с QR-кодами, история, возврат не позднее чем за час до сеанса.

**Администратор** (`/admin.html`)
- Обзор: выручка, онлайн-продажи, заполняемость, топ фильмов, последние заказы.
- Сеансы: расписание по дням, добавление (сервер проверяет, что зал свободен) и удаление.
- Фильмы: добавление и редактирование. Если на фильм уже куплены билеты онлайн, он не удаляется, а снимается с проката.
- Проверка билетов: контролёр сканирует QR камерой телефона, открывается страница проверки, кнопка «Пропустить в зал». Повторно по тому же билету не пропустит.

## Динамическое ценообразование

Цену всегда считает сервер (`server/pricing.js`). Цене, пришедшей из браузера, доверять нельзя.

```
цена = базовая цена фильма × зал × время сеанса × тип места × спрос × ранняя покупка
```

| Коэффициент | Значения |
|---|---|
| Зал | стандарт ×1.0, «Комфорт» ×1.2, IMAX ×1.5 |
| Время | утро (до 12:00) ×0.7, будний день (до 17:00) ×0.85, вечер и выходные ×1.0 |
| Место | обычное ×1.0, VIP ×1.3, диван ×1.4 |
| Спрос (заполненность) | от 40% ×1.05, от 60% ×1.15, от 80% ×1.25 |
| Ранняя покупка | за 3 и более дней до сеанса ×0.9 |

Результат округляется до 10 ₽. На странице выбора мест показано, из чего сложилась цена.

## База данных

```
cinemas ─< halls ─< seats
                 │
movies ─< sessions >┘          (сеанс = фильм + зал + время)
  │
  └─< movie_genres >─ genres

users ─< orders ─< tickets >─ seats      (билет = место на сеансе)
           │
           └─< order_snacks >─ snacks
users ─< auth_tokens
```

| Таблица | Назначение |
|---|---|
| `cinemas` | кинотеатры сети |
| `halls` | залы: тип, наценка, число рядов и мест |
| `seats` | места в зале: ряд, номер, тип (standard / vip / sofa) |
| `movies`, `genres`, `movie_genres` | фильмы и жанры (связь многие-ко-многим) |
| `sessions` | сеансы: фильм, зал, время начала, формат 2D/3D/IMAX |
| `users`, `auth_tokens` | пользователи (пароль хранится как хэш scrypt с солью) и токены входа |
| `orders` | заказы: pending → paid / expired / cancelled / refunded |
| `tickets` | билеты: место, цена, статус, уникальный код для QR |
| `snacks`, `order_snacks` | бар и предзаказ |

Главное ограничение — одно место на сеансе нельзя продать дважды. Его обеспечивает сама база, частичный уникальный индекс:

```sql
CREATE UNIQUE INDEX uq_ticket_seat ON tickets(session_id, seat_id)
    WHERE status IN ('reserved','paid','used');
```

Если два человека одновременно нажмут «Оплатить» на одно место, второй получит сообщение «Кто-то только что занял это место». Бронь создаётся в транзакции: все места заказа бронируются вместе либо ни одно.

Полная схема — в `server/schema.sql`.

## API

| Метод | Адрес | Что делает |
|---|---|---|
| POST | `/api/auth/register`, `/api/auth/login`, `/api/auth/logout` | регистрация, вход, выход |
| GET / PUT | `/api/me` | текущий пользователь / изменить профиль |
| GET | `/api/movies?status=now\|soon&genre=&cinema=&q=` | афиша |
| GET | `/api/movies/:id` | фильм и его сеансы |
| GET | `/api/sessions/:id` | схема зала с ценами и занятыми местами |
| POST | `/api/orders` | забронировать места `{sessionId, seatIds}` |
| GET | `/api/orders/:id` | детали заказа |
| POST | `/api/orders/:id/pay` | оплатить `{card, snacks}` |
| POST | `/api/orders/:id/cancel` | отменить бронь / вернуть билеты |
| GET | `/api/my/orders` | мои билеты |
| GET | `/api/tickets/:code/qr.svg` | QR-код билета |
| GET | `/api/admin/stats`, `/api/admin/movies`, `/api/admin/sessions` | админка |
| POST | `/api/admin/check` | проверить или погасить билет на входе |

## Технологии

- **Сервер:** Node.js. Используются встроенные модули `node:http`, `node:sqlite`, `node:crypto`, без фреймворков и библиотек.
- **База данных:** SQLite с внешними ключами, транзакциями и частичными индексами.
- **Клиент:** HTML, CSS и JavaScript (ES-модули), без фреймворков.
- **Безопасность:** пароли хэшируются scrypt с солью, сессия хранится в HttpOnly-cookie, цены и проверки только на сервере, есть защита от двойной продажи места и экранирование пользовательских данных при выводе.
